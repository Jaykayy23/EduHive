## Usage scenario, not a forecast

For a small synthetic evaluation month, assume 50 evaluators, 100 quiz generations, 200 tutor turns, 150 transactional emails (at most 30/day), 0.5 GB retained uploads, 50 monthly active chat users and 10 peak chat connections. Use measured token counts rather than document file bytes.

If each quiz uses 8,000 input tokens and 2,000 billable output/thinking tokens, the Gemini calculation is `100 × ((8000 / 1,000,000 × $0.30) + (2000 / 1,000,000 × $2.50)) = $0.74`. This covers only those assumed Gemini calls at the cited standard rates. Prompt overhead, thinking above the assumption, retries and changed pricing alter it. It excludes tutor usage entirely, which needs an account-specific quote. The app's context cap is not a token-metering guarantee.

That scenario fits the displayed email/storage numerical quotas, subject to provider eligibility/terms, other apps sharing quotas and daily limits. A commercial frontend, backend/database, backup policy and chat entitlement still need independent selection. The public fixed-sample demo makes **zero generation calls**; serving it still uses hosting resources. Live generation cannot be priced from demo clicks.
